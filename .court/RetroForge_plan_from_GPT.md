## 0. Claude에게 주는 최상위 명령

이 문서는 **승인된 구현 명세가 아닌 검증 대상 제안서**이다. 개발부터 시작하지 말 것.

1. 작업 환경, 저장소, Git 브랜치, 설치된 스킬(`/court` 포함), Codex/Gemini 연동 상태와 실행 권한을 먼저 검사한다. 연결 여부나 기능을 임의로 가정하지 않는다.
2. `court` 스킬의 실제 README/스킬 명세를 읽고, 이 기획의 **사업성·차별성·기술 범위·시간 대비 수익성**을 우선 심사한다. 기본 명령 예: `/court --quick ...`이나 CLI는 설치판이 제공하는 실제 문법만 사용한다. 사용자 승인 없는 추가 비용 발생을 금지한다.
3. Court 결과의 반론, 유죄 취지, 조건부 개선점을 `docs/decision_log.md`에 근거와 함께 기록한다. **Court 판정 자체를 시장 검증이나 실행 테스트의 증거로 취급하지 않는다.**
4. Court를 통과하거나 수정 조건이 분명한 경우에만 경쟁사·잠재 사용자의 문제를 재조사하고, MVP 요구사항과 수용 기준을 확정한다. 경제성이 부족하면 **NO-GO 또는 피벗**을 제안한다.
5. 구현은 Claude가 작업 단위를 정의해 Codex/Gemini에 분담한다. 실제 연결 도구가 없다면 미연결 상태를 보고하고 수동 전달용 이슈/프롬프트를 만들어 둔다. 연결된 척하거나 가상의 결과를 작성하지 않는다.
6. 모든 변경에 테스트 근거, 수행 주체, 변경된 파일, 남은 위험, 라이선스 출처를 기록한다. Court는 사전/마일스톤 의사결정용이며 CI·코드 리뷰·실기기 QA를 대신하지 않는다.
7. 판매·마케팅·계정 개설·지출은 사용자 승인 후 진행한다. 연령·결제/정산 자격 요건을 우회하지 않는다.

### 성공 정의

- **기술적 성공:** 처음 보는 Godot 개발자가 문서만 보고 데모에 RetroForge를 설치하고 효과를 켜고 끌 수 있으며, 지원을 약속한 환경에서 치명적 오류 없이 작동.
- **사용자 가치:** 개별 셰이더를 찾고 설정하는 시간을 줄이고, 프로젝트 전체의 스타일을 한 곳에서 관리.
- **사업 검증:** 실제 잠재 사용자의 문제 제기/설치 후기와 유료 수요 신호를 관측. 조회수나 Court 판정만으로 구매 수요를 주장하지 않음.
- **초기 범위:** 첫 버전은 핵심 효과 3~4개 + 프리셋/설치 UX에 한정. 범위를 넘기는 기능은 백로그로 분리.

## 1. 제품 가설과 목표 고객

**가설:** Godot 4에서 3D 레트로 게임을 만드는 1인·소규모 개발자는 단품 셰이더들을 연결하고 렌더러별 문제를 해결하는 데 시간을 소비한다. 쉽게 설치할 수 있고 호환성이 검증된 통합 툴킷에 비용을 지불할 일부 고객이 존재할 수 있다.

### 고객 세그먼트

- Godot 4 사용 경험은 있으나 셰이더 작성에 익숙하지 않은 게임 개발자.
- PS1풍 호러, 탐험, 로우폴리 3D 게임을 만드는 소규모 개발자.
- **차별화 후보:** 웹(Compatibility)과 Android 등 저사양 환경에서 시각 효과를 활용하려는 개발자.

### 가장 강한 반론

- 무료·저가 PSX 셰이더가 이미 많고 핵심 기능이 중복된다.
- PC/웹/Android 지원 약속에 비해 테스트 장비·시간이 부족하다.
- 자동 머티리얼 변환, 전역 API 등도 선행 제품이 이미 제공한다.
- 고객이 실제 돈을 낼 정도의 문제인지 증명되지 않았다.
- 학생 개발자의 학업/시간 제약 때문에 고객 지원·유지보수를 지속하기 어렵다.

### 경쟁 기준선 (가격은 조회 시점 공개값이며 변경 가능)

| 제품 | 공개 가격 | 주요 비교점 | URL |
|---|---:|---|---|
| PSX - Godot Shader | 무료 / 자율 지불 | vertex snapping, affine warp, dither, fog, 예제 | https://fcidade.itch.io/psx-godot-shader-free |
| PSX Look | $5.99 정가 | material conversion, 전역 설정, 다중 렌더러 표방 | https://heyheythere.itch.io/psx-look |
| Godot 4 Shader Pack | $4.99 | 13 shaders + demo | https://munchkin-jonesy.itch.io/godot-4-shader-pack |
| Retro Horror FX Toolkit | $4.99 정가 | 화면 효과 4종/프리셋 12종 | https://rastalr.itch.io/godot-4-retro-horror-fx-toolkit |

**검증 과제:** 직접 사용 가능한 대안의 구현·설치 편의·실행 성능을 평가하고, RetroForge가 *실질적으로* 해결할 미충족 문제를 한 줄로 제시할 것. 타 상품의 코드·에셋·상표/텍스처를 라이선스 없이 복제하지 말 것.

## 2. 목표 제품 및 제외 범위

### MVP 핵심 제공 가치

> 복잡한 셰이더 지식 없이 기존 Godot 4 프로젝트에 레트로 3D 룩을 적용·설정·비교할 수 있는 간결한 워크플로.

### P0: 첫 버전에 반드시 필요한 기능

1. **설치/제거 안전성:** `addons/retroforge/` 복사/활성화 가이드; 기존 프로젝트 파일을 파괴하지 않는 구조, 원복 경로.
2. **저해상도 픽셀화:** 내부 뷰포트 또는 호환 가능한 화면 효과 방식의 해상도 제어. 화면 비율 유지 및 UI 가독성에 대한 정책 포함.
3. **색상 양자화 및 선택적 디더링:** 색상 단계/패턴 강도 조절, 껐을 때 원래 화면 복원.
4. **정점 스냅 또는 간단한 PSX 머티리얼 효과:** 안정적 작동을 우선하고, 아핀 UV 왜곡은 기기 호환성 확인 후 포함.
5. **거리 안개:** 기본 환경/머티리얼 방식으로 구현 가능한 최소 기능; 렌더러별 차이를 명시.
6. **스타일 프리셋 최소 3종:** Subtle Retro / PSX Horror / Bright Low-Poly. 프리셋은 데이터 기반, 사용자가 수정 가능.
7. **Before/After 데모:** 같은 씬·카메라 상태에서 효과 토글 및 비교, FPS 표시 옵션.
8. **설치 문서 + 라이선스 + 호환성 표 + 변경 내역.**

### P1: 검증 후 확장할 항목

- EditorPlugin 도크(전역 설정 UI), 일괄 적용과 롤백 가능한 머티리얼 변환.
- 저장 가능한 사용자 프리셋, 범위별 적용(전체 씬/개별 오브젝트).
- 스크린 공간 dithering 개선, affine mapping/vertex wobble 품질 튜닝.
- 퍼포먼스 품질 단계(Low/Balanced/High), 모바일 및 웹 최적화 프리셋.
- 테스트 자동화와 예제 장면 추가.

### P2: 초기 판매 검증 전 제외

- N64·CRT·VHS·CCTV 모든 효과 동시 구현.
- 모든 Godot 4.x 버전/모든 GPU에 대한 무조건 호환성 보장.
- 모든 StandardMaterial3D의 완전 무손실 자동 변환.
- 독자적인 3D 월드 편집기/환경 에셋 대량 제작.
- 웹 서비스, 계정 시스템, 구독·라이선스 서버.

## 3. 기술 설계: 구현 전 검증 사항

### 필수 렌더러 정책

- **웹 내보내기 목표는 Compatibility + WebGL 2.0**: Godot 4의 웹 배포에서 Forward+/Mobile을 지원한다고 주장하지 않는다.
- Android 네이티브용 Mobile 또는 Compatibility와 Android 브라우저의 웹 Compatibility를 **서로 다른 테스트 타깃**으로 관리한다.
- PC Forward+는 별도 테스트 완료 전 지원 확정하지 않는다.
- GPU·브라우저·엔진 패치 버전별 결과를 매트릭스로 기록한다.
- `screen_texture`, `depth_texture`, 다중 전체 화면 패스의 비용/제약을 검증한다.
- 각 효과는 GPU 비용과 API 호환성을 고려해 graceful degradation(효과 개별 비활성화)을 지원한다.

### 품질·성능 테스트의 기본 설계

- 비교 장면 3종: 실내(동적 조명), 실외(원거리 안개), 다수 오브젝트(성능).
- 같은 장면에서 **효과 OFF vs ON** 비교: FPS 중앙값, 1% low 또는 프레임타임 분포(측정 가능 범위), 렌더 해상도, 기기 정보, 그래픽 드라이버/브라우저.
- 최초 측정 후 성능 기준을 정함. 예시 가설: 기준 씬 대비 프레임타임 증가가 모바일 웹에서 과도하지 않을 것. 임의의 FPS 보장을 홍보 문구로 쓰지 않음.
- 화면 비율 변경·리사이즈·UI 위 픽셀화·안개/투명체 오류·정점 스냅으로 인한 기하 흔들림·아핀 왜곡과 UV 경계 등을 시각 회귀 점검.
- 표본 장비가 태블릿 한 대라면 **그 장비에서 검증됨**이라고 표기하고, 광범위 호환성은 주장하지 않음.

## 4. AI 협업 오케스트레이션

### 에이전트의 명확한 책임

| 담당 | 주 역할 | 산출물 | 금지/주의 |
|---|---|---|---|
| Claude Code | 요구사항/이슈/브랜치 설계, 과업 분배, Court 운영, PR 통합, 릴리스 승인 제안 | backlog, acceptance criteria, decision log, release candidate | 시험하지 않은 기능에 승인 표시 금지 |
| Codex | P0 GDScript·shader 구현, 단위·통합 테스트, 호환성 개선 | 코드 PR, 테스트 로그, 기술 메모 | 다른 에이전트의 동일 파일에 동시 직접 수정 금지 |
| Gemini | 독립 아키텍처·성능·UX·문서 리뷰, 경쟁 대안 재검토 | review.md, 위험 목록, 수정 권고 | 자기 코드가 아님을 이유로 근거 없이 승인 금지 |
| Claude + 사용자 | 데모 실기기 실행, 시장 검증, 비용 및 출시 최종 결정 | test matrix, GO/NO-GO | 실제 사용자 의견을 모델 추측으로 대체 금지 |

### 실행 규약

1. GitHub `main`은 보호 가능한 안정 브랜치, 기능별 `feat/...`, 수정별 `fix/...` 사용.
2. 각 작업은 GitHub Issue로 발행한다. 필드: 목표, 전제, 변경 파일, 수용 조건, 테스트 명령, 위험, 담당자.
3. 각 에이전트는 독립 브랜치/워크트리 사용. 같은 파일 동시 쓰기는 Claude가 순차화.
4. Codex가 PR 제출 → Gemini 독립 리뷰 → Claude가 테스트 증거 확인 → 병합 결정. Claude 직접 구현의 경우 Codex를 리뷰어로 배정하여 자기 검증 방지.
5. 결정과 테스트 결과는 `docs/decision_log.md`, `docs/COMPATIBILITY.md`, PR 설명에 남긴다.
6. 스킬/API/에이전트 연결이 없으면 자동 호출을 가장하지 말고 해당 작업의 prompt/issue를 생성하고 사용자에게 연결 필요성을 알린다.
7. GitHub secret, API key, 계정 비밀번호, 개인 파일을 다른 에이전트의 프롬프트/로그/커밋에 포함하지 않는다.
8. 유료 모델 호출을 실행하기 전에 예상 비용과 호출 횟수의 상한을 사용자에게 보고한다.

## 5. Court 심사 계획 (사업 타당성 중심)

### Gate A — 개발 전 사전 심사

Court 질문 예시:

> 우리는 Godot 4용 PS1/레트로 그래픽 통합 툴킷 RetroForge를 2주 안에 무료 MVP로 검증하려 한다. 기존 무료 PSX 셰이더와 $4.99~5.99 유료 제품이 있으며, 핵심 제안은 쉬운 설치, 일관된 프리셋, 웹 Compatibility 렌더러와 안드로이드 중심의 검증이다. 초기 유료 가격 가설은 $9.99이나 아직 유료 수요 증거는 없다. Android 태블릿 주 개발 환경 및 학생 개발자의 제한적인 시간을 고려해, **이 계획을 중단해야 할 가장 강한 이유, 차별화의 허점, 기회비용, 저비용 검증 기준, 통과 조건**을 법정 형식으로 평가해 달라.

- 실제 설치된 court-skill README에 따라 `/court` 또는 `/court-skill:court` 실행.
- 비용/컨텍스트가 우려되면 `--quick` 사용 가능 여부 확인.
- `.court/VERDICT.md` 및 관련 산출물의 경로 기록.
- 유죄/무죄 다수결만으로 자동 승인하지 않고, **조건과 증거가 충족되는지** 다시 확인.

### Gate B — MVP 범위 심사

검증 질문: P0가 2주 안에 실현 가능한가? 가장 낮은 비용으로 가치 제안을 증명할 축소안이 있는가? 무엇을 제거해야 하는가?

### Gate C — 유료 전환 심사

검증 질문: 무료 대안 대비 지불할 이유가 있는가? 실제 테스트 데이터와 유저 피드백이 충분한가? 유료 가격/지원 약속이 과도한가?

**Court의 책임 한계:** 모델끼리 논쟁하는 도구이며, 버그 탐지·성능 프로파일링·판매량 예측·법률 판단을 대신하지 않는다.

## 7. 판매 및 사용자 검증

### 가격과 패키징 가설

- Free Lite: 핵심 효과 일부, 한 가지 데모, 기본 문서.
- Pro: 프리셋·편리한 통합 제어·추가 설정·테스트 완료 예제. 시험 판매가 `$7.99~$12.99`, 우선 비교 기준 `$9.99`.
- 가격은 **예상 적정가가 아니라 검증할 가설**. 상품 출시 전 $0/$4.99/$9.99 등 대안 가치와 고객 반응을 비교.

### 검증 지표 (시장 통계가 아닌 프로젝트 기준)

- 잠재 사용자 대화 10건 목표; 어떤 문제가 실제로 반복되는지 정성 분석.
- Lite 다운로드 30건 목표; 설치에 성공한 사용자 피드백 5건 목표.
- 구체적 지불 의향 3건을 탐색하되, 구두 의향은 실제 결제보다 약한 증거로 기록.
- 데모 다운로드뿐 아니라 설치 성공, 성능, 기존 프로젝트 적용률, 유지보수 질문을 측정.
- 유료 사용자가 생기지 않을 때는 기능 확대보다 문제·유입·가격·설명 중 병목을 조사.

### 출시에 필요한 조건

1. Godot 엔진 정확한 지원 버전과 렌더러별 검증 범위를 고지.
2. 예제 장면에서 치명적 오류 0건; 설치/제거 절차 검증.
3. 제3자 에셋·코드·텍스처·폰트·모델의 재배포 권한 검토; AI 생성물 포함 출처 기록.
4. 라이선스, 지원 범위, 버그 리포트 안내, 환불·판매 플랫폼 정책 확인.
5. 미성년 판매자/정산 자격은 보호자와 확인. 나이 제한 우회 금지.

## 8. 자동화 및 지속적 통합 (선택)

가능하면 GitHub Actions에서 다음을 실행한다. CI 지원이 확인되지 않으면 실행 불가로 기록한다.

- 프로젝트 import 및 Godot headless 에디터 구동 가능 여부.
- GDScript 정적 검사와 예제 씬 로드.
- 테스트 스크립트가 존재할 때 단위 테스트.
- 릴리스 zip 파일 내 누락 파일, 라이선스·README 유무.
- 비밀키/대용량 불필요 산출물 유출 검사.

**제한:** CI에서 headless 성공해도 WebGL 렌더링이나 Android GPU 동작이 검증되었다는 의미는 아니다. 실기기/실브라우저 스크린샷과 로그가 필요하다.

## 9. 최종 의사결정 규칙

**GO:** 무료 대안 대비 구체적인 고객 문제가 발견되고, MVP 핵심 워크플로가 설치·실행 테스트를 통과하며, 무리한 유지보수 약속 없이 제품을 운영 가능.

**PIVOT:** 무료 제품과 차별화가 약하면 Godot 에셋 임포트/정리 도구, 테마형 환경 패키지 등 다른 고객 문제로 전환.

**NO-GO:** 검증 가능한 환경에서 핵심 렌더링이 작동하지 않거나, 개선 비용이 기대 효익보다 크거나, 유료 수요 근거를 찾지 못할 경우.

사용자에게 보고할 때는 `완료/진행 중/검증 불가/실패`를 구분하고, 성공한 듯 묘사하지 않는다.
