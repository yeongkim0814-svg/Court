# Defense: the case should go ahead as described

1. **The downside is capped and the goal is modest.** The case says "Budget: up to 500,000 KRW may be spent" against a "Target profit: 1,000,000 KRW." The budget is a ceiling, not a requirement. Web hosting and deployment can be started at very low cost, so the user need not spend anywhere near the cap. The objection is that most side projects earn nothing. That is true, but the worst case is a small, bounded loss, and the target is a modest sum rather than a living wage.

2. **The time window fits.** The case says "from now, through the winter break, until university entrance." In Korea a senior's college-entrance exam period ends in November, and the user then has a long stretch of free time. The objection is that studying competes with this work. The record gives no study schedule, so I cannot show there is no conflict. The user chose this window knowingly, and the winter break is the natural slot for it.

3. **The user already has a production setup.** The case says: "the user has built an environment where Claude, Codex and Gemini collaborate on and review each other's work." This cuts the cost of building and reviewing code, which is the usual barrier for a non-professional. The objection is "not a professional developer." The setup is built to cover that gap, and the user has shown the initiative to assemble it.

4. **The goal pays for itself and teaches.** The money is for "AI subscription fees and other expenses." Even partial income offsets the running cost of the tools, and the work builds deployable skills alongside a physics degree plan. The objection is that profit comes "first." Profit as the priority is a clear decision rule, and it favors dropping weak ideas quickly.

**Concession:** The record does not say which games or websites, or how they would earn (ads, sales, subscriptions). The 1,000,000 KRW target has no stated basis. The case needs that plan, but it is a gap to fill, not a reason to stop.
